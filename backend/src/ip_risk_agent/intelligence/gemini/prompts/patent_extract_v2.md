문서에서 특허 검토에 필요한 기술 요소와 검색어를 뽑는다.

## 판단 기준

`is_technical` 은 다음을 모두 만족할 때만 참이다.

- 구체적인 처리 방식, 구조, 알고리즘, 장치 구성이 서술되어 있다
- 단순한 일정, 회의록, 사업 계획, 용어 정리가 아니다

기능 목록만 나열된 문서는 참이 아니다. 무엇을 어떻게 처리하는지가 있어야 한다.

## technical_elements

구성 요소를 한 줄씩 적는다. 문서에 실제로 서술된 것만 적는다.
일반적인 기술 상식을 보태지 않는다.

## search_queries

**한국 특허 데이터베이스(KIPRIS)에 넣을 한국어 검색어다.**
색인된 본문이 한국어이므로 영문 검색어는 결과가 0건이 된다.
문서가 영어로 쓰였더라도 검색어는 한국어 기술 용어로 만든다.

다음을 지킨다.

- **2 단어를 기본으로 한다.** 검색 엔진이 넣은 단어를 **모두** 포함하는 문서만
  찾으므로, 단어가 늘수록 결과가 급격히 줄어든다. 꼭 필요할 때만 3 단어로 한다
- 그 분야 특허 명세서에 실제로 쓰이는 기술 용어를 고른다.
  "데이터 처리", "시스템 구성" 같은 일반 명사 조합은 아무것도 걸러내지 못한다
- 서로 다른 관점을 담아 2~5 개를 만든다.
  하나가 0 건이어도 다른 검색어가 후보를 찾을 수 있게 한다
- 제품명이나 회사명은 넣지 않는다
- 영문 약어가 그 분야에서 그대로 통용되면 그대로 써도 된다

예 — 통화 음성에서 사기 패턴을 찾는 문서라면
`보이스피싱 탐지`, `화자 분리`, `음성 특징 추출` 처럼 만든다.

## source_segment_ids

각 판단의 근거가 된 입력 segment 의 ID 를 적는다. 입력에 없는 ID 를 만들지 않는다.

## 입력

```
{segments}
```
