# 요청: 대조 정밀도 측정용 교차 음성 쌍 데이터셋 (A셋 확장)

작성 2026-08-25, advanced_rag 브랜치 작업 세션. 수신: PatentComparison
골든셋(verification_pairs_157.csv) 작성자.

## 0. 요지

만들어 주신 157쌍 검증셋으로 대조 층의 **재현율**은 측정할 수 있게 됐는데,
**정밀도**(없는 걸 없다고 하는 능력)를 잴 음성 데이터가 없습니다. 157쌍
CSV를 **교차 재조합**하면 음성 쌍이 공짜로 나옵니다 — 이 재조합 데이터셋
제작을 부탁드립니다. 저희 쪽 측정 하네스는 준비되어 있어서 파일만 오면
즉시 v2/v3(RAG) 대조를 나란히 판정할 수 있습니다.

## 1. 지금까지의 특허 Risk 분석 고도화 흐름 (advanced_rag 쪽 진행 상황)

작업 진행도가 서로 다르니, 이쪽 상태를 먼저 요약합니다. 상세와 모든 실측
수치는 `docs/PATENT_RAG_ENHANCEMENT_PLAN.md` §7에 있습니다.

**검색·순위 층 (사실상 확정)** — 심사관 인용 골든셋(59출원, 다른 팀원 작성)
기준으로 병목을 분해해 세 번 갈아탔습니다.

| 단계 | 내용 | 심사관 인용 적중 (83건 중) |
|---|---|---|
| 기존 운영 | 전문검색 5건 + 적중수·위치 순위 | 2건 (2.4%) |
| fielded_v2 | 제목·초록 필드검색 60건 + 질의 확장 + **BM25 어휘 재순위** | 10건 (12%) |
| fielded_v3 | + **정밀꼬리**: 9~24위 중 "제목 필드 × 결과 30건 이하 질의" 적중을 판정 대상에 추가 | **13건 (16%)** · 건 단위 33% |

과정에서 확정된 사실: 검색 응답에 초록·등록번호가 실려 옴(재순위 공짜),
getAdvancedSearch 페이징은 pageNo/numOfRows(docsStart 무시), 검색 응답
초록은 689자에서 절단됨(히트의 13%), IPC는 순위 신호로 무효(풀이 이미
질의로 주제 필터링됨 — 오라클 부스트도 악화).

**대조 층 (미확정 — 이번 요청의 대상)** — 만들어 주신 157쌍으로 기존
대조(patent_compare_v2)와 신설 RAG 대조(청구항 조각 색인 + 요소 단위
검증)를 A/B 했습니다.

| 대조 방식 | 매칭 재현 (유일 쌍 125건) | 비고 |
|---|---|---|
| v2 (기존, 종합 판단) | 106/125 (85%) | 관대함 — 별도 실측에서 등급 HIGH 포화 경향 |
| v3 (RAG, 요소 단위) | 99/125 (79%) | 엄격함 — 대신 "청구항 N항 어느 부분" 조각 근거 제공 |

참고로 cost-logging의 `eval_patent_compare.py` 측정(92.4%)과 저희 85%는
**상충이 아니라 프로토콜 차이**입니다: 그쪽은 인용 공보 전문 8,000자를
프롬프트에 직접 넣었고, 저희는 운영 파이프라인과 같은 모양(KIPRIS 상세의
초록+청구항)을 넣었습니다. "전문을 주면 +7%p"라는 것 자체가 유용한
발견이라 입력 조건도 측정 축에 넣을 예정입니다.

**대조 층 설계 방향 (미확정)**: RAG 기반을 유지하되 기존의 관대한 종합
판정과 결합(하이브리드)하는 안을 검토 중이고, 판정 기준은 4가지입니다 —
① 근거 기반(조각 인용·검증) ② 높은 재현율 ③ **낮지 않은 정밀도** ④ 최종
사용자에게 보여줄 risk 후보·검토 우선순위의 정량화. 이 중 ③을 잴 데이터가
지금 없습니다 — 다른 팀원의 라벨0(무인용 등록)은 4건뿐이라 통계가 안 되고,
그래서 이 요청입니다.

## 2. 요청 내용 — 교차 음성 쌍 제작 명세

**원리**: 출원 X의 청구항(target_claims)과 **다른 출원 Y**의 인용 특허
(cited_fulltext)를 짝지으면, 두 발명이 서로 무관한 한 "매칭이 없어야
정답"인 음성 쌍이 됩니다. 157쌍 CSV 안의 재료만으로 만들 수 있습니다.

**안전 조건 (중요)**: 같은 분야끼리 교차되면 진짜 유사 선행기술일 수
있어 음성이 오염됩니다. 그래서:

1. **IPC 서브클래스(앞 4자리, 예: H01M)가 하나도 겹치지 않는 쌍만**
   채택합니다.
   - 출원 X의 IPC: KIPRIS 서지 조회 또는 기존 수집분.
   - 인용 특허의 IPC: cited_fulltext 상단의 `(51) Int. Cl.` 줄에서 추출
     가능합니다 (157건 전부 공개공보라 형식이 같습니다).
2. 같은 통지서(sendNumber)에서 유래한 쌍은 제외합니다 (당연히 양성).
3. 가능하면 **눈검수 10%** — IPC가 달라도 실질이 비슷한 쌍(예: 다른
   분류의 유사 기계장치)이 있으면 빼 주세요. 애매하면 빼는 쪽이 맞습니다
   (음성 셋의 순도가 지표의 신뢰도입니다).

**규모**: 약 100쌍이면 충분합니다. 출원이 한쪽에 몰리지 않게 여러 출원에서
골고루 뽑아 주세요 (출원당 최대 3~4쌍 권장).

**재현 가능성**: 무작위 추출을 쓰면 시드를 고정하고, 선정 절차(스크립트
또는 규칙)를 파일과 함께 남겨 주세요 — 나중에 셋을 키울 때 같은 절차로
만들어야 비교가 유지됩니다.

**형식**: verification_pairs_157.csv 와 같은 스키마(UTF-8)에 컬럼 2개 추가:

```
applicationNumber, sendNumber, target_claims, cited_식별자, cited_fulltext,
pair_label,        # 0 = 음성 (기존 157쌍은 1로 간주)
negative_basis     # 예: "ipc-disjoint(H01M vs A01K)" — 왜 음성인지
```

파일명 예: `negative_pairs_100.csv`, 위치는 기존 셋과 같은 폴더면 됩니다.

## 3. 이 데이터로 무엇을 재는가

저희 하네스(`scripts/evaluate_compare_pairs.py`)에 그대로 넣어 대조
방식별로 다음을 잽니다:

- **위양성률**: 음성 쌍에서 "매칭 있음"을 선언한 비율 — 정밀도의 직접 지표.
- **강도 분포 분리도**: 양성 쌍과 음성 쌍의 evidence_strength 분포가
  얼마나 갈라지는가 — 갈라져야 검토 우선순위 임계값(t_med/t_high)이 설
  자리가 생깁니다 (`docs/PATENT_PRIORITY_DESIGN_NOTE.md` §5의 "라벨 없이
  임계값을 고르지 않는다"가 이 데이터로 풀립니다).

이 두 숫자가 나오면 v2/v3/하이브리드 중 무엇을 최종 대조로 쓸지, 그리고
사용자에게 보여줄 HIGH/MEDIUM 경계를 어디에 둘지가 전부 측정 근거를 갖게
됩니다.
