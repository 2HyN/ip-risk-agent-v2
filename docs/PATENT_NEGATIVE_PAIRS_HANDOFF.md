# 요청: 특허 골든셋 "재료 데이터" 수집 — 교차·가공은 이쪽에서 한다

작성 2026-08-25 (v2 — 역할 분담 단순화 개정). 수신: PatentComparison
골든셋 작성자. **이 문서는 다른 모델(LLM 세션)이 받아서 그대로 이행할 수
있게 쓰였다.**

## 0. 한 줄 요지

교차 음성 쌍을 직접 만들지 않아도 된다. **교차 직전의 재료 3종**(출원별
청구항 / 인용 특허 전문 / 출원↔인용 매핑)만 아래 형식으로 수집해 주면,
IPC 확보·안전 교차·음성 쌍 구성·검색 평가셋 변환은 전부 advanced_rag
쪽에서 수행한다.

**이미 절반은 끝나 있다**: cost-logging 브랜치 커밋 `0486d1d` 의
`samples/patent/gold_target_claims_all.csv`(약 70출원) ·
`gold_cited_fulltext_all.csv` · `gold_reject_decisions_all.csv` 가 정확히
이 재료 형식이다. **요청 = 같은 형식으로 출원 수를 늘리는 것** (목표는
아래 §3).

## 1. 산출물 — CSV 3개 (기존 형식 그대로)

전부 UTF-8(BOM 허용), 기존 파일에 **행 추가** 방식. 새 파일로 내도 된다
(파일명에 `_batch2` 등 붙이기).

### A. `gold_target_claims_all.csv` — 출원별 청구항

| 컬럼 | 내용 |
|---|---|
| `applicationNumber` | 출원번호 13자리 숫자 |
| `claims` | 청구항 전체를 파이썬 리스트 문자열로: `['1. …', '2. …']` |

### B. `gold_cited_fulltext_all.csv` — 인용 특허 전문

| 컬럼 | 내용 |
|---|---|
| `식별자` | 공보 표기 그대로 (예: `공개특허공보 제10-2008-0027504호`) |
| `원문텍스트` | 공보 전문 텍스트. **상단의 서지부 — 특히 `(21) 출원번호` 와 `(51) Int. Cl.` 줄 — 가 잘리지 않게** (이쪽 자동 처리가 이 두 줄에 의존한다) |

### C. `gold_reject_decisions_all.csv` — 출원↔인용 매핑

| 컬럼 | 내용 |
|---|---|
| `applicationNumber` | 출원번호 |
| `kr_citations` | 인용 목록을 파이썬 리스트 문자열로: `[{'식별자': '공개특허공보 제10-…호'}, …]` (기존 형식의 추가 필드가 있어도 무방) |

## 2. 하지 **않아도** 되는 것 (전부 이쪽 소관)

- IPC 조회·대조 (출원 IPC 는 KIPRIS 로 이쪽이 조회, 인용 IPC 는 전문의
  `(51)` 줄에서 이쪽이 추출)
- 교차(음성 쌍 생성), IPC-서로소 안전 필터, 눈검수
- 번호 체계 해석(공보번호→출원번호), 초록 수집
- 검색 평가셋 변환

## 3. 규모와 우선순위

1. **1순위 — 새 출원 추가**: 현재 약 70출원. **+30~50출원**이면 통계가
   충분해진다. 조건: 거절결정 또는 의견제출통지서에서 심사관 인용이 확정된
   출원 (지금까지 모은 것과 같은 기준).
2. 2순위 — 기존 70출원 중 인용 전문이 빠진 것이 있으면 보충.

수집 절차·검수 기준은 지금까지 하던 방식 그대로다. 무작위 표본 추출을
쓰면 시드·조건을 커밋 메시지에 한 줄 남겨 달라 (재현 가능성).

## 4. 완료 판정 체크리스트 (받는 모델이 스스로 검증)

- [ ] CSV 3개가 UTF-8 로 읽히고 컬럼명이 §1 과 일치한다
- [ ] A 의 `claims` 와 C 의 `kr_citations` 가 `ast.literal_eval` 로 파싱된다
- [ ] C 의 모든 `식별자` 가 B 에 존재한다 (전문 누락 0)
- [ ] B 의 `원문텍스트` 90% 이상에서 `(21)` 과 `(51)` 줄이 정규식
      `\(21\)` / `\(51\)` 로 검출된다
- [ ] 새 출원이 기존 출원과 중복되지 않는다

체크리스트가 통과하면 cost-logging 브랜치에 커밋·푸시하고 알려 달라.

## 5. 이 재료로 이쪽이 만드는 것 (참고)

1. **대조 정밀도 셋**: IPC-서로소 교차 음성 쌍 (약한 음성이 아닌 안전
   음성). 참고로 `0486d1d` 의 무작위 음성 142쌍(재현율 92.4% · 정밀도
   75.1% · 오탐율 33.8%)은 이미 v2/v3 대조 A/B 에 투입 중이다 — 스스로
   명시한 "약한 음성" 한계를 IPC-서로소 판이 보완한다.
2. **대조 재현율 셋**: 출원 청구항 ↔ 확정 인용 (기존 157쌍의 확장).
3. **검색 평가셋 확장**: 각 출원이 검색 층(Layer R)의 테스트 케이스가
   된다 — 이쪽이 출원 초록을 조회해 "초록 → 검색 → 인용 회수율" 을 잰다.
   현재 37출원 기준으로 검색 고도화(2.4%→16%)를 측정했는데, 표본이 커질수록
   판정의 신뢰구간이 좁아진다.

## 6. 현재 진행 맥락 (요약)

검색·순위 층은 fielded_v3(판정 도달 13/83)까지 확정, 질의 생성 v4 +
클라이언트 결함 수정(AND 연산자·필드 캡)의 효과 측정이 진행 중이다. 대조
층은 v2(재현 85%/이쪽 프로토콜) vs v3(RAG, 79%) 비교까지 왔고, 정밀도
축이 이 재료에 달려 있다. 상세: `docs/PATENT_RAG_ENHANCEMENT_PLAN.md` §7.
