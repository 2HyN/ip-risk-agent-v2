방식대로 간다 — 저장소를 통째로 붙이지 않는다.

## 준비 — 폴더 하나를 만든다

| 파일 | 내용 | 무엇을 보려는가 |
|---|---|---|
| `requirements.txt` | `PyMuPDF==1.24.0` | **HIGH** — AGPL |
| `package.json` | `{"dependencies":{"chalk":"5.3.0"}}` | **MEDIUM** — MIT |
| `uv.lock` | `[[package]]`<br>`name = "pyarmor"`<br>`version = "9.2.6"` | **INDETERMINATE** — SPDX 가 어디에도 없다 |

## 2. 판정을 본다

Risks 목록에서:

| 기대 | |
|---|---|
| `pypi:pymupdf@1.24.0 — AGPL-3.0-ONLY` | **HIGH** |
| `npm:chalk@5.3.0 — MIT` | **MEDIUM** |
| `pypi:pyarmor@9.2.6 — UNKNOWN` | **INDETERMINATE** |

**INDETERMINATE 가 자기 칸에 있는지** 본다. HIGH 도 MEDIUM 도 아닌 네 번째 등급이다 —
"모른다" 는 심각도가 아니기 때문이다.

`pymupdf` 를 열어 근거를 본다. **AGPL 조항 문서**가 붙어 있어야 한다. 다른 라이선스의
문서가 붙어 있으면 그것이 가장 나쁜 오답이다.

> `LOW` 는 목록에 나타나지 않는다. 하 등급은 "낮은 위험" 이 아니라 **"관리 대상이
> 아니다"** 라는 판정이라 Risk 를 만들지 않는다 (결함 31).

## 3. 파일을 넣어 본다 — 이것이 핵심이다

폴더에 **파일을 하나 더** 넣는다.

```
constraints.txt      →  weasyprint==69.0
```

**마운트한 뒤에 넣은 파일이 잡혀야 한다.** 예전 Drive 는 이것이 안 됐다 — 마운트 시점의
명단에 없으면 영영 무시했다. 이 서비스를 쓰는 방법이 바로 그 "넣는 것" 이므로, 여기서
안 잡히면 기능이 없는 것과 같다.

Local 에서는 `constraints.txt` 가 **감시 대상에 들어온 것 자체**가 이번 변경이다.

---

## 4. 파일을 빼 본다

`package.json` 을 폴더 **밖으로** 옮긴다. 지우지 말고 옮긴다.

| 기대 | |
|---|---|
| `chalk` Risk | **RESOLVED · 제외됨** 으로 닫힌다 |
| 근거와 이력 | **그대로 남는다.** 지우지 않는다 |
| 나머지 Risk | 건드려지지 않는다 |

"알아보니 위험이 아니었다" 가 아니라 **"더 이상 보지 않는다"** 이다. 그래서 해소가 아니라
제외다.

---

## 5. 다시 넣어 본다

`package.json` 을 폴더 **안으로** 되돌린다.

- `chalk` Risk 가 **되살아난다**
- 4 번 전에 그 Risk 를 검토해 `수용`(ACCEPTED_RISK)으로 두었다면, **그 판단이 그대로
  복원된다** — 파일이 그대로면 사람의 판단도 그대로 유효하다

> 파일을 고쳐서 넣으면 `미검토` 로 다시 시작한다. "제외되어 있던 동안 세상이 달라졌다"
> 는 근거는 **판본이 달라진 경우에만** 선다.

## 6. 재검사

Sources 에서 파일 하나를 골라 **다시 검사**한다.

| 기대 | |
|---|---|
| 등급 | 그대로 |
| 근거 | **늘지 않는다** |
| 해소된 것 | 없다 |

같은 입력에 같은 결과가 나와야 한다. 재검사가 판정을 흔들면 그 판정을 믿을 수 없다.

## 무엇이 잘못됐다는 신호인가

| 보이면 | 뜻 |
|---|---|
| 폴더에 넣은 파일이 안 잡힌다 | 추적 범위가 명단으로 되돌아갔다 |
| 라이선스 Risk 가 0 건이다 | 의존성 파일이 감시에서 빠졌다 (Local 이 오래 그랬다) |
| 라이선스 위험이 **전부** 확인 필요다 | 배포 형태가 설정되지 않았다 (§5.10). 정하면 4·5 단계가 돈다 |
| 널리 쓰이는 패키지가 최고 위험이다 | 라이선스 전문에서 남의 라이선스를 읽었을 수 있다 (§5.13) |
| 폴더 밖으로 옮겼는데 Risk 가 남아 있다 | 이탈이 닫히지 않았다 |
| 되돌렸는데 `미검토` 로 돌아갔다 | 사람의 판단이 지워졌다 |

## 아직 안 되는 것

정직하게 적어 둔다.

* **배포 형태를 화면에서 못 정한다.** API 는 있으나(`PUT …/security/license-profile`)
  화면이 없다. 설정 전에는 라이선스 등급 대신 **확인 필요**가 나온다
* **배포 형태가 등급을 바꾸지 않는다** (결함 34). 사내 전용으로 바꿔도 AGPL 은 최고
  위험 그대로다 — 법적 판단이라 근거를 갖춘 뒤에 표를 나눈다
* **주기적 재평가는 하루 한 번** (03:30 KST). 그 자리에서 확인하려면 예약 작업을 손으로
  돌려야 한다
* **원인 표시가 화면에 없다.** 이력에는 있다 (3-B). 5 단계에서 붙인다
