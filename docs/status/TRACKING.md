각 세션은 자기 파일(`fork-*.md`)에 보고하고, 그것을 메인이 여기로 모은다. **여기 적힌
것이 합의된 현재 상태다.** 자기 파일과 이 문서가 어긋나면 이 문서가 맞다 — 어긋난 것을
발견하면 자기 파일에 적어 달라.

## 지금 막혀 있는 것 — 읽고 시작하라

**corpus 적재와 배포는 0-G 뒤다.** 지금 적재하면 안 된다.

`DEVELOPMENT_SPEC.md` §5.5 가 관련성 게이트를 **corpus 확대의 선행 조건**으로 못박아
두었다. 이유는 그 절에 적혀 있다 — 오부착을 막고 있던 것은 게이트가 아니라 **corpus 가
비어 있다는 우연**이었고, 문서를 늘리면 틀린 식별자마다 그럴듯한 문서가 하나씩 생긴다.

실제로 그렇게 됐다.

| | 확대 전 | 확대 후 |
|---|---|---|
| corpus 문서 | 3 편 | **73 편** |
| 게이트를 통과하는 질의 | 686 | **26,890** |
| 그중 오부착 | 318 (46.4%) | **7,902 (29.4%)** |

**비율은 좋아졌는데 양이 25 배가 됐다.** 아직 손해가 없는 이유는 하나뿐이다 —
`prepare_rag_ingestion.py` 가 dry-run 이라 **전문이 Vertex RAG 에 올라가 있지 않다.**
올리는 순간 7,902 건의 틀린 근거가 실제로 쓰이기 시작한다.

그래서 순서는 **0-G → 적재 → 배포**다. 0-G 는 메인이 다음에 한다.

## 측정 현재값

`DEVELOPMENT_SPEC.md` §10 의 표는 이 값들로 갱신되어야 한다 (아직 안 했다).

| 지표 | 명세에 적힌 값 | **지금** |
|---|---|---|
| corpus 커버리지 | 4/22 = 18.2% | **84/84 = 100%** |
| 오부착률 | 46.4% (686 중 318) | **29.4% (26,890 중 7,902)** |
| SPDX 어휘 (`_CANONICAL`) | 42 | **727** |
| 정책 분류 (`_OUTCOME_BY_ID`) | 42 | **158** |

**어휘와 정책의 대칭이 의도적으로 깨졌다.** 예전에는 둘이 정확히 같은 42 개였고 시험이
그것을 고정했다. 지금은 727 종을 **식별**하되 158 종만 **분류**한다. 나머지 569 종은
`UNKNOWN` 판정을 받지만 **식별자 문자열은 살아남는다** — 이것이 0-F(원문자열 보존)가
풀려던 문제의 상당 부분을 이미 푼다. 0-F 의 남은 몫은 727 종 밖의 것(사내 라이선스,
`LicenseRef-*`)이다.

## 이번 점검에서 나온 것

**내용은 하나도 잃지 않았다.** 시험 930 건 전부 통과하고,
`scripts/validate_gcp_deployment.py` 를 Fork A 와 Fork D 가 각각 고쳤는데 양쪽 변경이 모두
살아 있다 (서로 다른 자리를 고쳐 운이 좋았다).

**어긋난 것은 이력이다.**

* `366ffff` 는 메시지가 "docs(status): report Fork B's result" 인데 **81 개 파일**이 들어
  있다. Fork A 의 corpus 작업 전부(전문 70 편·빌더·매니페스트·색인·검증기)가 여기 담겼다.
* 그래서 Fork A 자신의 `3d45e84 feat(rag): build the corpus...` 에는 파일이 **1 개**뿐이다.
* `5e83336`(Fork D)은 Fork C 의 파일 둘을 함께 담아 갔다.
* `078c0f0`(메인)은 `docs/status` 를 통째로 스테이지했다. 그 안의 파일은 내가 만든
  것이라 손해는 없었지만 같은 습관이다.

원인은 하나다 — **파일 소유를 정해 두었지만 커밋 단계에는 그 규칙이 없었다.**
`git add` 와 `git commit` 사이에 다른 세션이 스테이지하면 그것이 함께 간다. Fork C 가
`4c40ab7` 에서 정확히 지적했다.

되돌리지 않는다. 이력을 다시 쓰면 이미 푸시된 것과 어긋나고, 내용이 온전하므로 얻는 것보다
잃는 것이 크다. **대신 규칙을 `README.md` 에 적었고, 앞으로는 그 규칙으로 막는다.**

**남은 어긋남 하나** — `RAG_CORPUS_VERSION` 은 배포 환경변수가 `2026-08-21.1`, 매니페스트가
`2026-08-23.2` 다. 검증기는 env **이름**만 보고 값은 못 본다. 배포 직전에 매니페스트 첫
줄을 보고 맞춰야 하며, 이건 코드가 잡아 주지 못한다. (`DEVELOPMENT_SPEC.md` §13-5)
