## 1-A — 서비스 계정 변경 피드 (**가장 먼저**)

폴더 하나를 서비스 계정에 뷰어로 공유한 뒤 셋을 본다.

1. 폴더에 파일을 새로 넣으면 SA 의 `changes` 에 잡히는가
2. 폴더 밖으로 옮기면 `removed` 로 오는가
3. 되돌리면 다시 나타나는가

셋 다 잡히면 이탈·재진입이 **이미 있는 DELETE / UPDATE 경로**로 들어와 폴더 대조 작업이
필요 없다. 안 잡히면 주기적 대조를 새로 만들어야 한다. **이 답이 설계 규모를 정한다.**

**v1 의 동작을 근거로 읽으면 안 된다.** v1 의 폴더 펼침은 연결 시점의 스냅샷이라 이후
들어온 파일은 추적되지 않았다(`ea70787`). v1 이 스코프를 넓힌 이유(`f50a15b`)도 펼치기가
409 로 실패해서였지 지속 추적 때문이 아니다.

## 1-B — 초기 스캔 비용

기본 제외 목록을 채운 상태로 실제 저장소 하나를 마운트해 **KIPRIS 실호출 수를 센다.**
`DEVELOPMENT_SPEC.md` §10 의 "초기 스캔" 칸이 이걸로 채워진다.

**KIPRIS 무료 등급은 월 1,000 회다. 다른 세션과 겹치면 안 된다** — 돌리기 전에 이 파일에
"지금부터 쓴다" 고 적어 달라.
