# 작업 현황 — 세션끼리 서로를 읽는 곳

여러 세션이 같은 저장소를 동시에 고친다. 각자 무엇을 하고 있고 무엇을 건드리는지 모르면
같은 파일을 두고 부딪히거나, 남이 이미 고친 것을 다시 고친다.

## 파일 배정

| 파일 | 누가 쓰는가 |
|---|---|
| **`TRACKING.md`** | **메인만.** 합의된 전체 현황이다. 나머지는 읽기만 한다 |
| `main.md` | 메인 (0 단계 개발) |
| `fork-a-rag-corpus.md` | Fork A (RAG corpus) |
| `fork-b-spdx-vocabulary.md` | Fork B (SPDX 어휘·예외) |
| `fork-c-measurement.md` | Fork C (실측) |
| `fork-d-deploy.md` | Fork D (빌드·배포) |

**남의 파일은 읽기만 한다.** 남에게 할 말은 **자기 파일에** 적는다 — "Fork A 에게: 색인
형식을 이렇게 기대한다" 처럼. 읽는 쪽이 자기 파일에 답한다.

`TRACKING.md` 와 자기 파일이 어긋나면 **`TRACKING.md` 가 맞다.** 어긋난 것을 발견하면
자기 파일에 적어 두면 메인이 접어 넣는다.

## 커밋 규칙 — 파일을 나눠도 커밋이 섞였다

실제로 일어난 일이다. `366ffff` 는 메시지가 "docs(status): report Fork B's result" 인데
**81 개 파일**이 들어 있고, 그 안에 Fork A 의 corpus 작업 전부가 담겼다. 그래서 Fork A
자신의 `feat(rag)` 커밋에는 파일이 하나뿐이다. 잃은 것은 없지만 이력이 거짓말을 한다.

원인은 **`git add` 와 `git commit` 사이**다. 그 틈에 다른 세션이 스테이지하면 함께 간다.

### 1. 스테이지와 커밋을 한 호출로 붙인다

틈을 없애는 것이 가장 확실하다.

```
git add <경로> <경로> && git commit -m ...
```

`git commit -- <경로>` 도 좋다 — 스테이지 영역을 아예 거치지 않는다.

### 2. `git add -A` · `git add .` · `git commit -a` 를 쓰지 않는다

디렉터리째 스테이지하는 것도 같다. `git add docs/status` 는 그 안의 남의 파일을 가져간다.
**경로를 하나씩 적는다.**

### 3. 커밋 직전에 무엇이 담겼는지 본다

```
git diff --cached --name-only
```

자기 소유가 아닌 경로가 하나라도 있으면 멈춘다. `git restore --staged <경로>` 로 뺀다.

### 4. 커밋 메시지는 실제로 담긴 파일을 설명한다

`docs(status)` 라고 적었으면 그 커밋에는 status 문서만 있어야 한다. 메시지와 내용이 다르면
나중에 무엇이 왜 바뀌었는지 되짚을 수 없다 — 이 저장소가 파는 것이 바로 그 능력이다.

### 5. 남의 파일을 고쳐야 하면 먼저 적는다

정말 필요할 때가 있다. Fork A 가 `pyproject.toml` 에 package-data 한 줄을 더해야 했던
것처럼. 그때는 **자기 상태 파일에 무엇을 왜 고쳤는지 적고** 커밋 메시지에도 남긴다.
말없이 고치지 않는다.

### 6. 브랜치

`integration-v3` 에만 커밋하고 푸시한다. **`integration-v2` 는 고정된 백업이라 건드리지
않는다.**

## 동시 작업 지침

### 순서 규칙은 소유권보다 세다

`DEVELOPMENT_SPEC.md` 가 정한 선행 관계는 **자기 파일만 건드려도 지켜야 한다.** 실제로
한 번 어긋났다 — corpus 확대(2-C)가 관련성 게이트(0-G)보다 먼저 들어가서, 오부착 후보가
318 건에서 7,902 건으로 늘었다. 파일은 안 겹쳤지만 **결과는 겹쳤다.**

자기 항목의 선행이 남의 소유라면 **기다리거나 물어본다.** `TRACKING.md` 의 "지금 막혀
있는 것" 을 시작 전에 읽는다.

### 외부에 나가는 것은 더 세다

적재·배포·실제 API 호출은 되돌릴 수 없다. **`TRACKING.md` 가 열어 주기 전에 하지
않는다.** KIPRIS 는 월 1,000 회라 두 세션이 겹치면 한도가 사라진다 — 쓰기 전에 자기
파일에 "지금부터 쓴다" 고 적는다.

### 시작할 때와 끝낼 때

* **시작** — `git log --oneline -10` 과 `TRACKING.md` 를 읽는다. 남이 이미 했을 수 있다.
* **끝** — 자기 상태 파일에 **끝난 것 · 쥐고 있던 파일 · 남이 알아야 할 것**을 적는다.
  진행률이나 소감은 적지 않는다. 다른 세션의 **행동을 바꾸는 것**만 적는다.

### 적지 않는 것

자격증명, KIPRIS 키, 로컬 절대경로. 시험 통과 수 같은 것도 적지 않는다 — `pytest` 를
돌리면 나온다.
