# 작업 현황 — 세션끼리 서로를 읽는 곳

여러 세션이 같은 저장소를 동시에 고친다. 각자 무엇을 하고 있고 무엇을 건드리는지 모르면
같은 파일을 두고 부딪히거나, 남이 이미 고친 것을 다시 고친다.

## 규칙 하나 — 한 세션은 자기 파일만 쓴다

| 세션 | 파일 |
|---|---|
| 메인 (0 단계 개발) | `main.md` |
| Fork A (RAG corpus) | `fork-a-rag-corpus.md` |
| Fork B (SPDX 어휘·예외) | `fork-b-spdx-vocabulary.md` |
| Fork C (실측) | `fork-c-measurement.md` |
| Fork D (빌드·배포) | `fork-d-deploy.md` |

**남의 파일은 읽기만 한다.** 이 규칙이 있어야 이 폴더 자체가 충돌 지점이 되지 않는다.
`DEVELOPMENT_SPEC.md` 를 두 세션이 동시에 쓰다 서로의 앵커가 깨진 적이 있어서, 여기서는
처음부터 파일을 나눈다.

남에게 할 말이 있으면 **자기 파일에** 적는다 — "Fork A 에게: corpus_coverage.json 의
형식을 이렇게 기대한다" 처럼. 읽는 쪽이 자기 파일에 답한다.

## 무엇을 적는가

세 가지면 충분하다.

* **지금 무엇을 하고 있나** — 끝난 것, 도는 것, 막힌 것
* **어떤 파일을 쥐고 있나** — 다른 세션이 피해야 할 경로
* **남이 알아야 할 것** — 새로 찾은 결함, 바뀐 전제, 부탁

진행률이나 소감은 적지 않는다. 다른 세션의 **행동을 바꾸는 것**만 적는다.

## 무엇을 적지 않는가

* 시험이 몇 개 통과했는지 같은 수치 — `pytest` 를 돌리면 나온다
* 코드에 이미 있는 설명 — 중복은 곧 어긋난다
* 자격증명, KIPRIS 키, 로컬 절대경로

## 이 폴더의 수명

0 단계가 끝나고 세션이 하나로 합쳐지면 이 폴더는 지운다. 그때의 결론은
`DEVELOPMENT_SPEC.md` 나 각 문서로 옮긴다. **여기 있는 것은 전부 임시다** — 규범으로
읽지 않는다.
